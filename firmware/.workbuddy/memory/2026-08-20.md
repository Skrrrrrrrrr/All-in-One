# 2026-08-20 工作日志

## 复盘 3 次 `reset` 指令"有时成功有时失败"
- 现象：3 次 `reset` 都成功重启到 CLI，但 flash 初始化路径不一致——有时 SFDP 签名
  校验通过（走 SFDP 路），有时报 `Check SFDP signature error` 再回退静态表。后者
  被误判为"失败"。PVD ISR 在 `reset` 后出现则说明这条 reset 走了"掉电看门狗"路径。

### 修复 1：关闭 SFDP，W25Q128BV 走静态表（确定性初始化）
- 文件：`Middlewares/Third_Party/SFUD/inc/sfud_cfg.h`
  `#define SFUD_USING_SFDP` → 注释掉（`// #define SFUD_USING_SFDP`）。
- 原因：本设备 flash 是**固定 W25Q128BV**（JEDEC ID 0xEF/0x40/0x18），SFUD 静态
  `flash_chip_table` 已有精确参数（16MB / 256B 页 / 4KB 擦除 0x20）。SFDP 探测多余，
  且在 flash reset 后偶发读到乱码签名 → 非确定性启动。关掉后 `sfud_init()` 永远走
  静态表匹配，日志从随机 "Found a Winbond flash chip"(SFDP) 变为稳定的
  "Found a Winbond W25Q128BV flash chip. Size is 16777216 bytes."。
- 验证：`sfud.c` / `sfud_sfdp.c` / `Sample-CLI-commands.c` 均独立编译零警告通过。

### 修复 2：加固 `prvResetCommand`，主动 reset 不被 PVD 看门狗劫持
- 文件：`Middlewares/Third_Party/FreeRTOS-Plus-CLI/Sample-CLI-commands.c`
- 该命令本已 `HAL_PWR_DisablePVD()` + 清 PVDO + 关 IRQ 再 `NVIC_SystemReset()`。
  新增在 `NVIC_SystemReset()` 前再 `g_pvd_trigger_count=0` / `__HAL_PWR_CLEAR_FLAG` /
  `EXTI->PR=PR16`，防止命令执行前瞬间锁存的 PVD 事件被 1ms poll handler 误读为掉电、
  从而劫持本次复位并打印 PVD ISR 噪声。
- 注意：`g_pvd_event_flag` 是 pvd_detection.c 的 static，外部清不了；但 DisablePVD +
  清 PVDO 后 poll handler 读到 PVDO=0 会自 abort，已足够。

## 结论给用户的要点
- reset 其实**每次都成功重启**，所谓"失败"= SFDP 偶发报错（已修，确定性启动）+ PVD
  ISR 噪声（已加固，且当前源码本就 disable PVD，重编即可干净复位）。
- 若重编后仍见 PVD ISR：说明是真实 VDD 微跌触发看门狗（少数板子电源边际），非 reset 命令 bug。
